# 한국어 리라이팅 원칙

원본의 열 가지 원칙을 사실과 목소리를 보존하는 범위에서 적용한다.

## 1. 한 문장에 중심 하나

독자가 주체·행동·조건을 놓치는 문장은 나눈다. 서로 연결된 짧은 내용을 억지로 분리하거나 원문의 우선순위를 새로 정하지 않는다.

## 2. 호흡

필요한 긴 설명 뒤에 짧은 핵심 문장을 놓는다. 문장 수를 맞추려고 정보를 더하거나 빼지 않는다. 문단은 메시지가 바뀌는 곳에서 나눈다.

## 3. 추상을 구체로

제공된 자료의 숫자·명사·행동으로 바꾼다. 원문이 `많은 사용자가 불편해한다`뿐이면 사용자 수를 만들어 쓰지 않는다. `사용자들이 불편을 겪는다`처럼 원래 범위에서 다듬거나 불편의 내용과 근거를 확인할 항목으로 남긴다.

## 4. 불필요한 반복 줄이기

같은 뜻을 거듭 설명하는 문장은 합친다. 같은 개념은 같은 이름으로 부른다. 제품명·기술 용어·지표는 반복돼도 동의어로 교체하지 않는다.

## 5. 종결어와 문체

원작자의 격식과 제품·조직 문체를 따른다. 같은 종결어가 반복되면 문장 구조로 리듬을 조절한다. 반복 회피만을 위해 합쇼체와 해요체를 뒤섞지 않는다. 사용자가 원하면 문체를 전체적으로 통일한다.

## 6. 부사 절제

부사를 지웠을 때 뜻·범위·속도·감정이 달라지는지 확인한다. `빠르게`를 없애도 되는지와 시간을 구체화할 근거가 있는지는 다른 문제다. 원문에 없는 `30분` 같은 숫자를 붙이지 않는다.

## 7. 단락의 첫 문장

첫 문장에서 핵심이 보이게 한다. 인과관계가 입증되지 않았으면 `영향일 수 있다`를 `때문이다`로 바꾸지 않는다. 회고·에세이의 의도한 전개는 보존한다.

## 8. 명확한 호명

자료로 누구를 가리키는지 알 수 있으면 이름이나 역할을 쓴다. 알 수 없으면 집단·인원·직책을 지어내지 않는다. `우리`의 범위가 의미를 좌우하면 확인한다.

## 9. 단정과 불확실성

확실한 사실은 명확히 쓰고, 추정·가능성·조건은 드러낸다.

- 전: 아마 이 변경이 도움이 될 수도 있을 것 같습니다.
- 후: 이 변경이 도움이 될 수 있습니다.
- 실제 자료에 효과가 확인된 사례가 있다면 그 범위와 출처를 함께 쓴다. 사례가 없으면 효과가 확인됐다고 쓰지 않는다.

## 10. 목소리 보존

원작자의 결론·의도·개성·격식을 유지한다. 분량과 구조 변경은 요청 범위에 맞춘다. 직접 인용, 코드, 명령, URL과 식별자는 표현상의 군더더기처럼 취급하지 않는다.

## 장르와 검토

업무 메일은 요청·맥락·제공된 기한을 선명하게, 보고서는 사실·해석·출처를 구분해, UI는 실제 상태·행동을 정확하게 쓴다. 기술 문서는 사용자 조작과 시스템 자동 동작을 구분한다. 블로그·SNS는 원작자의 경험과 리듬을 살린다.

수정 후 원문과 수치·날짜·조건·의무·인용·결론을 대조한다. 독자가 같은 사실을 더 쉽게 이해하는지 확인한다. 해결하지 못한 정보 빈칸은 숨기지 않는다.
