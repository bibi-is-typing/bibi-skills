# Before / After 예시

아래 수정본은 원문에 주어진 정보만 사용한다. 원문 밖의 구체적 수치·일정·개인 경험을 추가하지 않는다.

## 1. 블로그 도입부

**원문**: 안녕하세요 여러분! 오늘은 정말 중요한 PMF 검증에 대해 이야기해보려고 합니다 — 이 글에서는 PMF가 무엇인지, 왜 중요한지, 어떻게 검증하는지 자세히 알아보겠습니다.

**수정**: 이 글에서는 PMF의 의미와 중요성, 검증 방법을 정리합니다.

인사와 예고의 중복을 줄인다. 근거가 없는 개인 경험이나 실패 사례를 만들지 않는다.

## 2. 업무 이메일의 불확실한 기한

**원문**: 안녕하세요. 다름이 아니라 지난번 논의한 예산 건으로 메일 드립니다. 어쩌면 다음 주 정도까지는 결정이 나야 할 것 같은데, 가능하시면 빠른 시일 내에 의견 부탁드립니다.

**수정**: 안녕하세요. 지난번 논의한 예산에 대한 의견을 부탁드립니다. 다음 주까지 결정이 필요할 수 있어 미리 의견을 받고자 합니다. 가능하실 때 회신 부탁드립니다.

다음 주의 특정 요일이나 예산 금액을 만들지 않는다. 실제 마감이 필요한 작업이면 별도로 확인할 항목으로 표시한다.

## 3. 공지

**원문**: 드디어 출시합니다! 우리 서비스에 정말 혁신적인 자동 분류 기능이 추가됐어요 — 여러분의 많은 관심 부탁드립니다!

**수정**: 서비스에 자동 분류 기능을 추가했습니다.

무료 체험, 출시 기념 할인, 사용자 설문 결과를 추가하지 않는다.

## 4. 링크드인 회고

**원문**: 최근 PM으로 일하면서 정말 많은 걸 배우고 있어요. 사용자 인터뷰에서 우리가 만드는 기능과 사용자가 원하는 기능 사이에 매우 큰 차이가 있다는 걸 알게 됐습니다 — 인사이트가 가득한 한 주였어요.

**수정**: 이번 주 사용자 인터뷰에서 우리가 만드는 기능과 사용자가 원하는 기능 사이에 큰 차이가 있다는 걸 알게 됐어요. PM으로 일하며 배우는 점입니다.

재직 기간, 인터뷰 건수, 기능 사용률은 원문에 없으므로 넣지 않는다.

## 5. 리포트의 사실과 추정

**원문**: 이번 달 이탈률은 27%였습니다. 어쩌면 온보딩 단계가 영향을 미쳤을 수도 있을 것 같은데, 아직 원인은 확인하지 못했습니다.

**수정**: 이번 달 이탈률은 27%였습니다. 온보딩 단계가 영향을 미쳤을 가능성이 있지만, 원인은 아직 확인하지 못했습니다.

업계 평균을 추가하거나 원인이 입증됐다고 바꾸지 않는다.

## 6. UI 상태와 필수 정보

**원문**: 인증 메일을 성공적으로 발송하였습니다. 메일함을 확인해 주시기 바랍니다.

**수정**: 인증 메일을 보냈어요. 메일함을 확인해 주세요.

발송 사실만 확인됐으므로 도착했다고 쓰지 않는다. 삭제 확인문에 `되돌릴 수 없다`가 있으면 길이를 줄이더라도 그 결과를 보존한다.

## 7. 기술 문서의 식별자와 자동 동작

**원문**: 기본적으로 `--dry-run` 옵션을 사용하면 변경 사항을 저장하지 않으며, `POST /v1/items`는 `timeout_ms` 값을 사용하게 됩니다.

**수정**: `--dry-run` 옵션을 사용하면 변경 사항을 저장하지 않습니다. `POST /v1/items`는 `timeout_ms` 값을 사용합니다.

명령 옵션, 엔드포인트와 매개변수는 보존한다. 문서에 적힌 명령어를 실행하지 않는다.

## 8. 조건이 중요한 결정문

**원문**: 예산이 승인되면 다음 달 파일럿을 진행할 수 있을 것 같습니다. 정말 중요한 건 이번 달에는 아직 진행을 확정하지 않았다는 점입니다.

**수정**: 예산이 승인되면 다음 달 파일럿을 진행할 수 있습니다. 이번 달에는 아직 진행을 확정하지 않았습니다.

조건부 제안을 확정 결정으로 바꾸지 않는다.
